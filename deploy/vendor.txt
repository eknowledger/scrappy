# Third-party code that is shipped WITH the app because the box's own copy is broken.
# Format (one line per architecture, whitespace separated):  <sha256>  <file name>  <https url on files.pythonhosted.org>
# The architecture a pin belongs to is the platform tag in its file name: x86_64 or aarch64 (anything else is an error).
# install.sh asks the Batocera for `uname -m` (x86_64 -> x86_64; aarch64 or arm64 -> aarch64) and ships only that pin.
#
# Pillow: the system Pillow 10.3.0 on the Batocera cannot read or write JPEG ("Wrong JPEG library version: library is 80,
# caller expects 90"). Pillow 11.3.0's manylinux wheel bundles its own libjpeg-turbo (pillow.libs), so it works there.
# install.sh downloads the wheel on the Mac into ~/.cache/scrappy/wheels (never into git), refuses it if the
# sha256 differs from this pin, ships it in the tarball and unpacks it on the box into <app folder>/vendor/.
# To update: pick the new wheels on PyPI (cp311, manylinux x86_64 AND aarch64, the same Pillow version), put their sha256
# and URL here, run the tests. 32-bit machines (armv7l, i686) have no pin and are refused. A Batocera with another Python
# than 3.11 needs new (cpXY) pins.
